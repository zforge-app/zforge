# Finder menu scene (website capture)

Material for the "Menu no Finder" picture of the website's feature gallery
(`zforge-website`, section "O que mais o Zforge faz"): Finder's real shortcut
menu for an archive, with the Zforge item highlighted and its submenu open.

- `Documentos/` — the fictional folder the capture opens in Finder, generated by
  [`../../Scripts/website-captures/make_fixtures.py`](../../Scripts/website-captures/make_fixtures.py)
  (the same folder the app captures and the website's demonstration use;
  `Fotos-2025.7z` is the archive whose menu is captured).
- `capture_finder_menu.py` — the capture script. It regenerates `Documentos/`,
  puts Brazilian Portuguese first in the preferred languages and relaunches
  Finder and the Zforge Finder extension, unregisters the extension of a
  Zforge installed in `/Applications` for the duration (so Finder runs the
  extension of a current build, whose titles it checks), opens the folder in
  Icons, opens the menu on `Fotos-2025.7z`, hovers the Zforge item and captures,
  in the current appearance and then in the other one. Afterwards it restores
  the languages, the registration and the appearance and relaunches Finder.
- `Captures/finder-menu-light.png`, `Captures/finder-menu-dark.png` — the raw
  captures: the window's icon view only (no sidebar, toolbar or path bar), at
  the display's density.

- `Captures/<lang>/` — the same raw captures in the other app languages
  (`capture_finder_menu.py --lang`), with `menu.json`: the Finder and Zforge
  titles and frames that were captured, and any title that differs from the
  extension's String Catalog.

Other languages: `--lang de` (repeatable), `--lang others` (every language but
Brazilian Portuguese) or `--lang all`. Each language gets its own sample folder,
with the names and texts of
[`../../Scripts/website-captures/fixture_names.json`](../../Scripts/website-captures/fixture_names.json)
(translations awaiting the owner's review), made in a temporary folder and
removed afterwards; Finder is put in that language and relaunched for it. The
menus are read through the accessibility API (Finder's items by action, such as
`cmdArchive:` for Compress), so the frame is the same in every language: from the
Compress item down, 26 points left of the menu, 28 right of the submenu and 26
below it. The archive must sort among the first items of its folder: an archive
sorted last opens the menu too far right and the submenu on the left of it (the
script stops). Finder has no Bengali localization: with `--lang bn` its own items
fall back to the next preferred language, and only the Zforge submenu is Bengali.

The framed pictures go to `--out DIR` as `finder-light.png` and
`finder-dark.png`; the website's `scripts/import-feature-captures.mjs DIR`
encodes them (other languages: `DIR/<lang>/`, encoded with `--lang others --only
finder` into `public/features/<lang>/`), together with the app captures of
[`../../Scripts/website-captures/capture_app.py`](../../Scripts/website-captures/capture_app.py).

## Running it

```sh
Documentation/FinderMenuScene/capture_finder_menu.py --out /tmp/zforge-website-captures
Documentation/FinderMenuScene/capture_finder_menu.py --out /tmp/zforge-website-captures --lang others
```

Requirements: an unlocked session, a current Zforge build registered with
pluginkit (building the app with Xcode or `capture_app.py` registers it), and
the Accessibility and Screen Recording permissions for the terminal. The
script moves the pointer and brings Finder to the front for about a minute;
do not use the Mac while it runs (about 45 seconds per language). Every
click and key goes only to Finder, and only while Finder is the frontmost app. If a step fails, it saves the icon view to
`$TMPDIR/zforge-finder-menu-failure-<lang>.png` and still restores the system state.
