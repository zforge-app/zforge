### Folders fixed in Favorites — 2026-10-03

- “Add to Sidebar” in the contextual menu native shared (`BrowserNativeContextMenu`) adds the selection when all items are real folders, excluding packages and virtual directories of archives. The command is disabled when all are already pinned. Remove only the visible entry “Add Folder...”; pin per menu/scratcher, store, bookmarks and native selection action preserved.
- Favorites header inserts at the beginning. Each favorite has its own delegate: the first 5 pt insert before it, the last 5 pt insert before the next favorite (or at the end when it is the last), and the body transfers files. The Locations header also receives the pin at the end, keeping the final position accessible without another entry visible. With empty Favorites, the header itself allows pin. Fix does not copy or move files. Alternative B, refined in 20:22, uses accent line of 2 pt, cast circle of 8 pt/count of 2 pt and start 8 pt to the left of the content. Vertical inserts of the zeroed cell and padding of the plyed button maintain the height, with the indicator centered on the full edge of the line; the last favorite also draws the bottom line. The indicator is painted by a transparent NSView above the table clip view, anchored to the cell position, so as not to be cut by it; the layer does not participate in Hit Testing and Accompany Scroll. It has its own backing layer; by updating the anchor, your zPosition is above all sister layers, including added highlights later. There is no global handler of List or cell geometry preferences.
- The sidebar retains the original symbols during drag. The destination receives solid accent background with text/white symbol; the current folder uses monochromatic background without outline and semibold name. The comparison is with the current actual folder by canonical path, not with its ancestors; Recents, filters and virtual location of archive do not highlight a real folder. The drag color has priority and the gray selection returns on exit.
- Sidebar icon tint follows Finder (user request, 2026-10-29): Recents and Favorites use the accent color; Locations rows (the computer, home, local and removable volumes, Network and any other row of that section) and mounted network volumes use the neutral `secondaryLabelColor`. While the window does not appear active (`appearsActive` false: not key/main), every row icon uses `tertiaryLabelColor`, as Finder's inactive icons; a drop target keeps the white icon on its accent background. Finder tag dots keep their tag color while the window is active and turn the same `tertiaryLabelColor` as the icons while it is inactive (user request, 2026-10-30, `SidebarTagDot`; uncolored tags keep their outline in that gray). Row names follow the window state in every section, as in Finder (user request, 2026-10-30): primary while active (a selected tag uses the accent color; a drop target white) and `secondaryLabelColor` for every name while the window is inactive. All rows (destinations, the computer and Network through `SidebarVirtualLocationRow`, Recents through `SidebarActionRow`, tags) apply the shared `sidebarLabelStyle`, so no section stays white while another grays out. The role is set per section through the `sidebarIconTint` environment value and applied by the shared `sidebarIconStyle` modifier. [BrowserNavigationViews.swift](../../Zforge/Views/BrowserNavigationViews.swift); evidence in `REGRESSION-COVERAGE.md`.
- Computer item in Locations (user request, 2026-10-29; reverses the earlier conversational decision that Zforge did not need Finder's computer shortcut in the sidebar, which had left Locations with only home and volumes and was never recorded as a requirement): the first Locations row, before home and the volumes, as in Finder. Its title is the system computer name (`SCDynamicStoreCopyComputerName`, falling back to `Host.localizedName`, then the localized “Computer”), shown verbatim and never hardcoded; it is re-read when the sidebar refreshes (launch, mount/unmount/rename) and when Zforge becomes active, so renaming the Mac in System Settings appears on return. The symbol follows the Mac's model family through the system device-model type hierarchy (`hw.model` → `com.apple.device-model-code` UTType): `laptopcomputer` for laptops, `macmini`, `macstudio`, `macpro.gen3`, otherwise `desktopcomputer`; it uses the Locations neutral tint. The row is highlighted (semibold, unemphasized selection background) while the window shows the computer level, and it accepts no drops. Its sidebar kind is `SidebarLocationKind.computer` (`SidebarComputer`), for the Locations context menu. Visibility: the `computer` category of Settings ▸ Sidebar (titled with the computer name), shown by default; “Remove from Sidebar” hides it.
- Computer level (`BrowserLocation.computer`), opened by the computer item and **Go ▸ Computer** (`⇧⌘C`, which previously opened `/`): Finder's Computer window contents — every browsable mounted volume (`VolumeCatalogService`, hidden volumes skipped, including network shares) as a container item with its volume name and native icon, then **Network**, always listed (user request, 2026-10-30: “Também não tem o Network”; the earlier rule listed it only when a `/Network` folder existed, which never happens on macOS 26, where Finder's Network is a virtual node), with the system network icon (`com.apple.network-neighborhood`). Network sorts with the volumes by the shared sort, as in Finder. Window title and the single path-bar component are the computer name with its model symbol; there is no proxy icon. All four modes list these items with the shared sort; Columns uses the computer level as the root column, opening a volume adds its column beside it and keeps the computer root; List can expand a volume inline. Opening or expanding a volume from this level uses the same access grant as its sidebar row: without a grant the authorization sheet appears and the window stays on the computer level (after approval the volume opens as a new root). Inside a volume opened from here the path bar is `Computer name > Volume > …`, Enclosing Folder (`⌘↑`) returns to the computer level, and Back/Forward record it like any location. The level is virtual: no new folder, paste, drop, file operation destination or directory monitor; mount, unmount and volume rename refresh it (also as the root column while a volume column is active). Items keep their file identity, so selecting a removable volume enables File ▸ Eject. Commands that would modify a volume root (Duplicate, Compress, Move to Trash) are not specially disabled at this level; the system rejects them with its error (pending polish, TASKS). Volume roots, here and wherever they appear in the content views, show the system icon of their volume type (`NSWorkspace.icon(forFile:)`: internal disk, removable or external drive, disk image, network volume) instead of the composed folder icon (user request, 2026-10-30). A volume root listed in the content views (at the computer level or anywhere else, detected by `URLResourceValues.isVolume`) cannot be renamed (user decision, 2026-10-30, OR-25): `FileBrowserState.canRename(_:)` excludes it, so the File ▸ Rename item and its Return shortcut, the toolbar's More menu and the item's context menu show Rename disabled, and `beginRenaming(_:)` refuses it, in all four view modes; moving its mount point is never attempted (an earlier inline rename failed with “couldn't be moved because you don't have permission to access “Volumes””, and the interim routing through the volume rename was removed with it). Ordinary items keep the inline rename.
- Network level (`BrowserLocation.network`; user request, 2026-10-30), opened by the Network item of the computer level and **Go ▸ Network** (`⇧⌘K`, as in Finder; it previously opened the nonexistent `/Network` folder): Finder's Network window contents — file servers discovered on the local network over Bonjour (`NWBrowser`, `_smb._tcp` and `_afpovertcp._tcp` in `local.`; `BonjourNetworkServerBrowser` in [NetworkDiscovery.swift](../../Zforge/Services/NetworkDiscovery.swift)). A server advertising both protocols is one entry; each shows the system file-server icon (`com.apple.file-server`). The path bar and title are `Computer name › Network` (Go ▸ Network builds the same path, with Network selected in the computer column); Enclosing Folder returns to the computer level; Back/Forward record it. Discovery runs only while the path contains the Network level (also as a column) and is cancelled when it leaves the path or the window closes; servers appear and disappear live, the selection of the remaining servers is kept, and an update never clears a shown error. A bar at the top of the level (`NetworkLevelBar`, every view mode, whether or not servers were found, its size independent of the server list) holds **Add Remote…**, which opens the window's connect-to-server sheet through the same entry point as Go ▸ Remote (`FileBrowserState.showServerConnection()`); the sheet connects by SMB, AFP or NFS address and opens the mounted share (user request, 2026-10-30: it replaces the sidebar's Shared ▸ Remote row). While no server is known the level is simply empty below the bar: no “No Servers Found” notice and no spinner (removed at the user's request, 2026-10-30; discovery keeps running). When Local Network privacy blocks browsing and no server is known it shows “Local Network Access Is Off” with an **Open Privacy Settings** button below the bar (kept: it is the only explanation for an empty level and leads to the fix, while Add Remote still connects by address). The level is read-only like the computer level (no new folder, paste, drop, file operation destination, monitor, inline List expansion or preview). Servers are not containers (a single click in Columns only selects them); opening one (double-click, Return, File ▸ Open) connects through the system's connect flow — not the Add Remote sheet: `NSWorkspace.open` of the Bonjour address (`smb://Name._smb._tcp.local`, AFP only for AFP-only servers), where the system authenticates and lets the user pick a share — then waits for the network volume's mount notification and opens the share through the sidebar navigation (with its folder authorization). An already mounted share of the same host opens directly. A failure keeps the level and shows “The server could not be opened.”; a newer request, leaving the level or closing the window cancels the wait without navigating. The system mount also opens a Finder window for the share (sandbox: Zforge cannot mount with NetFS itself; see OPEN-REQUIREMENTS). Info.plist declares `NSBonjourServices` and a localized `NSLocalNetworkUsageDescription` (`InfoPlist.xcstrings`). ### Durable tag index and bounded retries — 2026-10-06

The production shared catalog persists tagged records, authorized scope paths/inodes, per-volume FSEvents journal UUIDs, **per-scope** processed cursors and explicit deferred paths. Storage is an atomic, versioned, private application-support file; encoding/I/O run in a serialized background actor. Authorization precedes probing/restoration. A saved index cannot add grants or expand the visible Home/Shared policy. Missing/corrupt storage, incompatible schema, replaced scopes, invalid volume identity or future cursors require discovery. Unavailable persistent history falls back to live monitoring plus discovery.

Each matching authorized scope restores independently, validates visibility in a bounded background batch, replays offline events and retries saved deferred paths. Valid history avoids blanket tag-metadata rereads for ordinary cached files. Symbolic links, multiply linked regular files and unavailable item identities receive conservative metadata rereads because their changes may escape the watched path. Home/Shared grants can arrive separately, including a process ending between grants: checkpoints preserve disjoint ungranted scope data on disk without publishing it; later authorization still requires identity validation. Each device-relative stream watches exactly one scope, even when scopes share a volume. Streams begin before first discovery; HistoryDone orders historical delivery. Cold traversal starts after history delivery so already-incorporated changes do not repeat that first pass. File events update metadata; new/moved/visibility-changed directories reconcile affected subtrees, including inode metadata changes. Dropped events, wrapped IDs and root changes reconcile all watched scopes on the affected volume. Only drained, applied work advances the stored checkpoint. Interrupted traversal cannot save unfinished work.

An uninterrupted traversal saves a **partial** index when access/I/O errors leave deferred items. The snapshot explicitly remains incomplete; reopen retries those items/subtrees instead of all accessible Home files. Failed metadata reads retain known records instead of manufacturing empty tags; successful reconciliation clears covered retries. Error paths are bounded to 512 before conservative scope coalescing and stay inside authorized discovery boundaries. Hidden failures do not schedule discovery or defer their accessible parent. Root authorization failure does not mark the scope covered, allowing later grants to be processed.

Accepted live events join a fixed 350 ms reconciliation window; later events cannot restart it indefinitely, and ignored hidden noise cannot schedule work. Hidden ancestry is checked from the root down, stopping before descendants; a maximum of 512 ancestor-flag entries is shared within one synchronous event batch and discarded afterward so visibility transitions are fresh.

Traversal batches native directory names, object types, hidden flags and optional xattr-presence information in a 32 KiB buffer per active directory. Only a confirmed EF_NO_XATTRS bit permits skipping a tag-metadata syscall; missing flags and symlinks retain reads. Stat fallback preserves symlink type. Package contents are excluded even when a package itself is an explicit rescan root. Unsupported filesystems retain the characterized Foundation fallback. Root/item path identity is preserved, including system-path aliases. Utility priority, the 128-item/8 ms work budget, cancellation and no periodic post-completion worker remain; the former 20% cooperative duty target was removed by the user on 2026-10-24. Index memory scales with genuine tagged records; these are bounded working buffers, not a hard application quota.
