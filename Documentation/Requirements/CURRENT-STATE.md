## 5. Preview, Quick Look, information and sharing

### Icon content previews — 2026-10-05

- `Show previews in icon view` is an application preference, enabled when no value is saved. Both enabled and disabled choices persist across launches and apply immediately to open windows. It is independent of each mode's inspector visibility and affects only grid cells in Icons. List, Columns, Gallery and their selection previews retain their contracts.
- Visible Icons cells request content without selecting the file or opening the inspector. Raster images use bounded ImageIO decoding, SVG uses the system content provider, PDFs show the first page, plain text uses the existing 1 KiB buffer, and HTML uses a static WebKit snapshot with document JavaScript disabled and relative resources scoped to the containing directory. Other noncontainer formats request a content representation from macOS Quick Look Thumbnailing; available providers determine support. Native file/folder/archive icons remain the fallback during loading, when disabled, or when content is unavailable. The static-icon descriptions elsewhere refer to this fallback and the other modes.
- Thumbnails fit the existing 64 pt square (scaled with zoom) without cropping or changing cell/hit-target geometry. Hidden-file opacity and selection backgrounds remain shared. Loading does not animate geometry or depend on motion preferences. Zoom retains the current file's raster until its replacement arrives; item revisions clear previous content. Each cell cancels its request when removed, replaced, resized or disabled; obsolete results cannot replace current content. The name remains the accessible label, with a selected trait; image decoration does not duplicate the label.
- The shared single/double-click recognizer captures modifier flags from the originating mouse-down in the cell's visible window. Releasing Command/Shift while waiting to distinguish a double click cannot change the selection action. Icons, List, Columns and Gallery use this same capture and preserve their existing single/double-click actions. [FinderClickGesture.swift](../../Zforge/Views/FinderClickGesture.swift).
- The grid permits up to four concurrent requests, two native bitmap decoders and one HTML renderer. Memory cache is limited to 256 entries/16 MiB with a maximum 256 px image dimension; item metadata revisions and pixel size invalidate it. Unsupported representations are cached; transient errors retain fallback without modal alerts. Archive thumbnail materialization is serialized and uses `.preview` session storage, independently of the inspector. Only known-size entries up to 10 MiB load automatically; larger or unknown-size entries retain icons and their existing explicit preview action. Hiding the inspector stops its own materialization, while enabled Icons thumbnails remain active.
- Concurrent archive materializations merge their cache entries into the live session after extraction. Closing or cancelling a session discards completed obsolete output instead of restoring the captured session. Native integration tests reproduce both old failures and verify the correction.
- Implementation: [IconPreviewService.swift](../../Zforge/Services/IconPreviewService.swift), [IconPreviewRenderer.swift](../../Zforge/Services/IconPreviewRenderer.swift), [FileBrowserPreferences.swift](../../Zforge/Models/FileBrowserPreferences.swift), [ArchiveEngine.swift](../../Zforge/Services/ArchiveEngine.swift). Executed tests, visual evidence, performance measurements and remaining matrix limits are recorded separately in [REGRESSION-COVERAGE.md](../../REGRESSION-COVERAGE.md).

- `⌘⇧P` alternates the active mode preview; each mode persists its own visibility. Icons/List show side panel, Columns adds preview only for eligible selection, Gallery controls inspector maintaining hero. ### Durable tag index and bounded retries — 2026-10-06

The production shared catalog persists tagged records, authorized scope paths/inodes, per-volume FSEvents journal UUIDs, **per-scope** processed cursors and explicit deferred paths. Storage is an atomic, versioned, private application-support file; encoding/I/O run in a serialized background actor. Authorization precedes probing/restoration. A saved index cannot add grants or expand the visible Home/Shared policy. Missing/corrupt storage, incompatible schema, replaced scopes, invalid volume identity or future cursors require discovery. Unavailable persistent history falls back to live monitoring plus discovery.

Each matching authorized scope restores independently, validates visibility in a bounded background batch, replays offline events and retries saved deferred paths. Valid history avoids blanket tag-metadata rereads for ordinary cached files. Symbolic links, multiply linked regular files and unavailable item identities receive conservative metadata rereads because their changes may escape the watched path. Home/Shared grants can arrive separately, including a process ending between grants: checkpoints preserve disjoint ungranted scope data on disk without publishing it; later authorization still requires identity validation. Each device-relative stream watches exactly one scope, even when scopes share a volume. Streams begin before first discovery; HistoryDone orders historical delivery. Cold traversal starts after history delivery so already-incorporated changes do not repeat that first pass. File events update metadata; new/moved/visibility-changed directories reconcile affected subtrees, including inode metadata changes. Dropped events, wrapped IDs and root changes reconcile all watched scopes on the affected volume. Only drained, applied work advances the stored checkpoint. Interrupted traversal cannot save unfinished work.

An uninterrupted traversal saves a **partial** index when access/I/O errors leave deferred items. The snapshot explicitly remains incomplete; reopen retries those items/subtrees instead of all accessible Home files. Failed metadata reads retain known records instead of manufacturing empty tags; successful reconciliation clears covered retries. Error paths are bounded to 512 before conservative scope coalescing and stay inside authorized discovery boundaries. Hidden failures do not schedule discovery or defer their accessible parent. Root authorization failure does not mark the scope covered, allowing later grants to be processed.

Accepted live events join a fixed 350 ms reconciliation window; later events cannot restart it indefinitely, and ignored hidden noise cannot schedule work. Hidden ancestry is checked from the root down, stopping before descendants; a maximum of 512 ancestor-flag entries is shared within one synchronous event batch and discarded afterward so visibility transitions are fresh.

Traversal batches native directory names, object types, hidden flags and optional xattr-presence information in a 32 KiB buffer per active directory. Only a confirmed EF_NO_XATTRS bit permits skipping a tag-metadata syscall; missing flags and symlinks retain reads. Stat fallback preserves symlink type. Package contents are excluded even when a package itself is an explicit rescan root. Unsupported filesystems retain the characterized Foundation fallback. Root/item path identity is preserved, including system-path aliases. Utility priority, the 128-item/8 ms work budget, 20% cooperative duty target, cancellation and no periodic post-completion worker remain. Index memory scales with genuine tagged records; these are bounded working buffers, not a hard application quota.
