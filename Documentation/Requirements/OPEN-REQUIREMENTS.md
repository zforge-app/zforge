### OR-20 decision — Consolidate redundant automation folder grants (2026-10-07; implemented and verified within the recorded matrix)

The user approves keeping the automation grant list minimal: after explicitly authorizing a parent directory, remove persisted descendant grants covered by that parent. Adding a directory already covered by a valid parent should likewise avoid a redundant entry. Apply the shared policy to Settings and contextual consent from Shortcuts/MCP. The shared grant store now consolidates usable covering parents and descendants; final regression passes 294 cases / 386 executions with zero failures/skips, and the actual installed Settings consolidation/revocation sequence passes.

Recommended safeguards: create and validate the replacement parent bookmark before removing covered entries; commit the change atomically, retain existing entries on failure, compare resolved physical directory boundaries rather than string prefixes, and preserve leases held by running operations. A symlink lexically under the parent but resolving outside it is not covered and must retain its independent grant. Revoking the consolidated parent removes future access to all covered descendants; removed child grants must not silently reappear. Record this revocation consequence as part of the intended user-facing contract. Implementation and the recorded regression/native Settings sequence are delivered. Broader OR-20 conditions remain separate.
